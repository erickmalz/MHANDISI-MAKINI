# Voice and copy

**Precise. Helpful. Human.**

Write like a capable colleague who knows the site engineer has limited time.
Start with what happened, or what the user needs to do.

---

## Core messaging

| | |
|---|---|
| Official tagline | **Let's build together** |
| Short description (EN) | Construction project management for the site engineer. |
| Short description (SW) | Usimamizi wa miradi ya ujenzi kwa mhandisi wa eneo la kazi. |
| Brand meaning | MHANDISI MAKINI — Swahili for "Very Keen Engineer" |

The tagline uses this **exact wording, sentence case and apostrophe**. Keep it
in English unless a separate translation is approved. Place it outside the
logo's clear space, visually smaller than the brand name. Omit it on small
applications rather than let it become unreadable.

Earlier proposed taglines are retired. Do not revive them.

---

## Name

- `MHANDISI MAKINI` — formal brand references.
- `Mhandisi Makini` — running prose where title case is needed.
- Unchanged in English and Swahili. Never translated, abbreviated or hyphenated.

| Moment | English | Swahili |
|---|---|---|
| Primary action | Create daily report | Andaa ripoti ya siku |
| Confirmed save | Report saved. | Ripoti imehifadhiwa. |
| Required field | Enter the project name. | Weka jina la mradi. |
| Empty state | No tasks yet. Add your first task. | Hakuna kazi bado. Ongeza kazi yako ya kwanza. |
| Failed submission | Report not submitted. Try again. | Ripoti haijatumwa. Jaribu tena. |

Match the selected interface language throughout each screen; do not switch
languages without a reason. Swahili strings run longer than English — let text
wrap; never truncate an essential instruction to fit a fixed box.

Review Swahili terminology with intended users before release.

## Writing rules

**Do**

- Active verbs, specific nouns, short sentences.
- Describe the problem *and* the useful next step.
- Sentence case for headings, buttons and navigation.
- Units next to values: `25 m²`, `12 mm`, `TZS 150,000`.
- Unambiguous dates: `06 Sep 2026`.

**Don't**

- Blame the user.
- Manufacture urgency.
- Use jargon or raw technical codes as the explanation.
- Make unsupported promises: "zero delays", "guaranteed safety", "perfect
  project control", "best app ever".
- Stack competing calls to action.
- Set paragraphs entirely in capitals.

---

## Honesty rules

These are non-negotiable, because the app records site work that people rely on.

- Never say "Saved" or "Submitted" before the action is confirmed.
- If local saving and syncing both exist, distinguish them clearly.
- Don't guess the cause of an error:
  - Confirmed connection failure → "Report not submitted. Check your connection
    and try again."
  - Unknown failure → "Report not submitted. Try again."
- Never expose a raw error code as the only explanation.
- Never present unverified claims about savings, safety or project outcomes as
  facts.
- Never use the brand checkmark to imply a safety inspection or technical
  approval occurred.

---

## Campaign copy

One message, one call to action, one relevant destination.

Good shape:

> **MHANDISI MAKINI** (small, on charcoal)
> **Let's build together** (hero)
> For the site engineer. (support)
> [ Discover the app ] (one yellow button)

Bad shape — the guidelines' explicit counter-example:

> BUILD! PLAN! TRACK! / BEST APP EVER! / CLICK NOW! JOIN NOW!

Only say "Join the waitlist" if a working waitlist actually exists.

---

## Personality

Capable, attentive, composed, direct. An organised professional colleague.

Avoid boastful claims, playful construction cartoons, and unnecessarily
technical language.
